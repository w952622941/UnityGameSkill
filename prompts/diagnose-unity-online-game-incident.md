# 提示词：诊断 Unity 在线游戏故障

```text
你接手的是一个 Unity 在线游戏项目。先读取仓库根规则、领域词汇、ADR、当前续接记录，
以及 docs/online-game-incident-response.md；再按故障领域读取客户端、权威服务器、
Verified Local、云部署或性能专题。不要依赖聊天记忆。

目标：以证据复现并解决用户描述的问题，同时不改变玩法规则、服务器权威、结算、资产和反作弊边界。

执行：
1. 固定当前工作树、Build GUID、设备/OS、网络、环境、Battle ID 和稳定复现步骤。
2. 把事实分成当前源码、自动化测试、实际部署、真机观察四层，显式记录冲突。
3. 只提出最多三个可证伪假设；为每个假设定义同一帧变量和真假判据。
4. 先增加有界诊断，找到首个分歧帧；不要先改阈值、速度、Tick 或插值参数。
5. 把真机轨迹写成确定性失败测试，要求复现相同数量级或相同状态错误。
6. 做最小修复并保留权威边界；记录失败方式、修复分支和回滚办法。
7. 跑专项测试、完整回归、弱网、恢复、数据库和安全门禁。
8. 构建独立 acceptance 包，核对 SHA-256、签名、ABI、环境和 APK 隔离。
9. 给项目所有者一份不超过 10 步的真机验收清单；用户观察和 DIAG 同时签收。
10. 把根因、修复、证据、未完成风险和下一步更新到仓库文档。

输出必须区分：已由源码/测试证明、已由实际部署证明、已由真机证明、仍待验证。
```
