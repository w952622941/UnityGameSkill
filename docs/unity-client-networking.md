# Unity 手机网游客户端实施指南

客户端的目标不是“拥有最终真相”，而是把输入、即时反馈、可恢复状态和诊断证据做得可靠。以下方法已在 Android 真机问题中验证有效。

## 分层

- **输入适配层**：触摸、摇杆、按键、生命周期事件。
- **本地模拟/预测层**：固定 Tick 的确定性核心或实时模式下的有限预测。
- **网络层**：HTTPS 负责登录、配置、存档和资产；WSS 负责实时输入、确认、快照与重连。
- **表现层**：插值、动画、音效、HUD，不写永久资产。
- **恢复与诊断层**：续战标记、证据续传、DIAG 报告。

## 摇杆与移动：用最新状态邮箱

移动方向是连续状态，不是必须逐条执行的命令队列。

1. 将方向量化并附带单调递增序号。
2. 邮箱只保留“最新待发送方向”和“等待确认方向”。
3. 网络发送频率与模拟 Tick 解耦；拥塞时覆盖旧方向，而不是积压上千条。
4. 在 `PointerUp`、`PointerCancel`、拖出有效区域、失焦、暂停、禁用和销毁时立即写入零方向。
5. 本地表现必须在一次渲染帧内停止；网络确认可以稍后到达。

这套规则修复了“松开摇杆后角色继续朝一个方向移动”和高延迟下输入积压放大的问题。

## 预测、插值与纠偏

- 自己的角色可用已确认状态 + 未确认输入重放做预测。
- 收到服务器状态后，从确认序号丢弃已处理输入，再重放剩余输入。
- 敌人只在两份已证明快照之间插值；没有证据时不要无限外推。
- 旧 Tick 或旧租约快照必须丢弃，不能倒放当前状态。
- 纠偏应有阈值：小误差平滑，大误差快速归位并记录 DIAG，而不是始终慢慢追赶。

Verified Local 模式没有每步网络纠偏：客户端即时模拟，服务器稍后重放校验。表现层仍然不能修改确定性状态。

## 每场战斗状态必须彻底隔离

在进入新战斗前重置：

- 等级、经验、击杀、战斗金币和计时器
- 初始技能弹窗及“已选择”标记
- 生成器、技能调度器、对象池活动项
- 输入序号、快照游标、验证状态和本地证据批次
- 终局、退出、复活和续战标记

持久化续战标记只在真实终局后清除。应用被杀时保留它；主动退出完成后清除它。TF_2D 曾出现第二场继承第一场等级、重复技能弹窗和错误续战提示，这一隔离规则已用于修复。

## Unity 主线程边界

Unity API 只能在允许的线程调用。路径、对象、场景和多数 Unity 属性不要在后台任务或字段初始化器中访问。曾验证的故障是后台保存调用 `Application.persistentDataPath` 导致异常；解决方式是在主线程预取路径或把 Unity API 调用移到 `Awake/Start`，后台线程只处理纯数据和文件工作。

## 终局 UI

- 死亡、胜利、主动退出分别呈现。
- 一旦本地或服务器状态机确认终局，先显示结果，再异步刷新永久资产。
- “等待服务器验证”是独立状态，不能把画面无限卡在死亡现场。
- 网络重试必须幂等；关闭和重新打开客户端仍能查询同一验证/结算结果。

## Android 兼容基线

至少覆盖：

- API 22/23、26、29、31、33、35
- ARM64、IL2CPP、GLES3 与项目启用时的 Vulkan
- 60/90/120 Hz、长宽屏、刘海/挖孔和安全区
- 前后台、锁屏、来电、权限弹窗、低内存回收
- Wi-Fi/蜂窝切换、断网恢复、无 Google Mobile Services 的华为设备
- APK/AAB 正确签名和目标商店要求

平台完整性服务只能是风险信号，不能成为所有 Android 设备的唯一通行证。

## DIAG 最小字段

一份可用报告应包含：

- 应用版本、Build GUID、Unity/IL2CPP、设备、OS、图形 API、帧率和内存
- 环境、脱敏后的 API/WSS 主机、协议/模拟器/内容版本与内容哈希
- `battleId`、模式、状态、客户端 Tick、服务器 Tick、快照年龄
- 最新输入序号/确认序号、移动方向、租约版本、重连次数
- 玩家/敌人/投射物数量、战斗时间、击杀、战斗金币和展示金币
- 证据批次、上传游标、检查点哈希、首次分歧 Tick、拒绝码
- 验证/结算状态、幂等键结果、资产账本版本
- 本地模拟、网络、表现和恢复阶段耗时

报告必须能在游戏内复制并可关闭；不得包含访问令牌、私钥、完整账号凭据或个人敏感数据。
