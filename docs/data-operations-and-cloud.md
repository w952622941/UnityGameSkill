# 配置、运营数据与可迁移云部署

网络游戏从第一天就应让配置、权威资产、分析数据和基础设施彼此解耦。这样既便于运营后台统计，也能在更换云服务器或暂时没有云服务器时保持可控行为。

## Excel 配置流水线

Excel 是策划输入，不是运行时格式。

1. Excel 源文件放在项目之外的独立目录，不进入 APK，也不直接由服务器运行时读取。
2. 不预先按领域创建工作表；业务需要时再登记新表。
3. 编译器拒绝未登记且非空的工作表、未知列、重复主键、类型错误、宏和外部链接。
4. 列声明受众：Client、Server 或 Both；分别生成客户端与服务器 JSON/二进制产物。
5. 按稳定键排序、规范化序列化并计算内容哈希。
6. 发布清单记录版本、哈希、生成器版本和源文件摘要。
7. 一场运行中的战斗固定内容哈希，热更新不能改变其中途规则。

客户端产物只能包含显示和本地模拟需要的数据；掉率、反作弊阈值、付费规则和服务端秘密不进入 APK。

## 运营事件模型

业务写入权威数据库后，通过事务 Outbox 发布事件。事件至少包含：

- 事件 ID、发生时间、玩家/战斗匿名标识
- 协议、模拟器、内容和客户端版本
- 事件类型与事实等级
- 服务器结算值、验证状态、风险标签
- 关联 ID，便于从后台追踪到日志/DIAG

运营后台消费这些事件生成留存、漏斗、关卡、经济、设备和网络质量统计。分析数据库故障不能阻断资产结算；统计修正也不能直接改余额。

## 可迁移云部署

- 客户端只认识所有者控制的稳定 HTTPS/WSS 域名，不硬编码 VM IP、供应商域名、SSH 地址或容器地址。
- development、staging、production 使用独立配置和凭据；生产不能静默回退到开发地址。
- 后端采用标准 Docker/Compose 起步，状态放 PostgreSQL/对象存储，容器保持无状态。
- 密钥、数据库口令和签名材料由环境/秘密管理器注入，不进入 Git、镜像、APK、日志或聊天。
- 数据库迁移可前滚/回滚，应用健康检查区分存活与就绪。

没有可信后端时，普通本地 PvE可以继续计算并保留待验证证据，但永久资产必须等待服务器验证。离线不是“自动信任客户端”的理由。

## 云迁移顺序

1. 导出配置、镜像版本、数据库与对象存储备份。
2. 在新环境实际执行恢复演练，而不只确认“备份文件存在”。
3. 用 staging 域名验证健康、登录、存档、资产、战斗、回放、结算和重连。
4. 使用 Release 构建做容量与回放基准。
5. 降低 DNS TTL，安排旧环境只读/短暂停写窗口。
6. 切换稳定域名，观察错误率、延迟、队列和账本一致性。
7. 保留可执行回滚方案，确认稳定后再下线旧环境。

Quick Tunnel 在临时真机验收仍有用，但它的随机域名、额外 RTT 和会话寿命不满足生产实时战斗要求。生产应使用固定域名、有效证书和持久 WSS。

## 发布清单

每次服务端/客户端发布记录：Git 提交、镜像摘要、APK/AAB 摘要、协议/模拟器/内容版本、数据库迁移版本、配置哈希、回滚目标和验证证据。这样更换服务器不会改变战斗规则，也能解释任意一笔结算来自哪个版本。
